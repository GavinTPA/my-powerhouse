# setup-vault — Technical Reference

## Purpose

Configures a member's Obsidian vault as a working Knowledge Vault and connects it to Claude Code via Smart Connections MCP.

## What It Sets Up

| Component | Files Modified | Restart Required |
|-----------|---------------|-----------------|
| Templates folder | `{vault}/Templates/` | No |
| Zettelkasten folder | `{vault}/Zettelkasten/` | No |
| Daily note template | `{vault}/Templates/Daily Note.md` | No |
| Core plugins enabled | `{vault}/.obsidian/core-plugins.json` | Obsidian restart |
| Daily notes config | `{vault}/.obsidian/daily-notes.json` | Obsidian restart |
| Templates config | `{vault}/.obsidian/templates.json` | No (hot-reloads) |
| SC MCP server | `~/smart-connections-mcp/` | Claude Code restart |
| MCP connection | `~/.mcp.json` | Claude Code restart |

## Prerequisites

1. Obsidian installed with MAGI vault created
2. Smart Connections plugin installed and enabled
3. python3 (3.10-3.13) for MCP server
4. git for cloning MCP repo

## Smart Connections MCP Architecture

The MCP server (`dan6684/smart-connections-mcp`) is a Python process that:
1. Reads `.smart-env/multi/*.ajson` embedding files generated by the SC Obsidian plugin
2. Loads embeddings into memory on startup
3. Serves semantic search via MCP stdio transport
4. Claude Code connects to it via `~/.mcp.json`

The server does NOT read markdown files directly — it uses pre-computed embeddings from the SC plugin.

## Vault Discovery

Searches in order:
1. `~/Documents/MAGI/`
2. `~/Documents/COPYobsidian/MAGI/`
3. `~/MAGI/`
4. `find ~/Documents -maxdepth 3 -name ".obsidian" -type d`

## Known Issues

- `numpy<2.0` pinned in requirements.txt — numpy 2.x breaks imports
- `brew upgrade` can remove Python versions that the venv depends on
- `install.sh` in the SC MCP repo overwrites `~/.mcp.json` — skill merges instead
- First-time embedding load takes 2-3 seconds, queries are 100-200ms after
